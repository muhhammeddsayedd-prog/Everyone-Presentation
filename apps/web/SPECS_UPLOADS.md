# Private original-document readiness

The server admits PDF, macro-free DOCX and UTF-8 text originals up to 20 MiB.
`specs-original.ts` checks file signatures and structure before a completion
receipt is signed. PDF admission checks the header, cross-reference target and
terminal EOF; it does not extract text or establish that every PDF object is
readable. DOCX admission checks bounded ZIP expansion, CRC32, required Word
package metadata, unsafe paths/macros and XML declarations/relationships. The
isolated worker owns actual extraction, page/text limits and scanned-PDF errors.

`CENTRAL_SPECS_UPLOADS_ENABLED` defaults to false. A true flag additionally needs
a canonical 32-byte `SPECS_VERIFICATION_KEY_BASE64URL` and
`SPECS_VERIFICATION_KEY_ID`, separate from the logo key. The server uses only the
fixed `eps-specs-assets` bucket. It advertises uploads only when the central DB
also advertises the `specs` purpose. Ready original reads remain available if
new-upload verification is missing or invalid.

Local development may load the dedicated pair from the protected files below.
Importing the loader reads nothing; only the central development launcher invokes
it. Existing nonempty process/file configuration keeps normal precedence.

- `.local/specs-assets-verifier/verifier.json`: compact canonical JSON plus LF,
  containing only `SPECS_VERIFICATION_KEY_ID` and
  `SPECS_VERIFICATION_KEY_BASE64URL`.
- `.local/specs-assets-verifier/phase.json`: canonical JSON with two-space
  indentation plus LF, exactly `version`, `target`, `key_id`, `phase`, `claim_id`,
  `secret_file`, `created_at`, `completed_at`, `contains_secret`.

The completed phase must use version 1, target `pyibofyctwnqpvktepse`, key ID
`eps-specs-dev-20261029-v1`, phase `completed`, a UUIDv4 claim, the exact secret
path above, valid timestamps with completion at or after creation, and
`contains_secret: false`. The loader rejects partial pairs, symlinks, unexpected
paths, oversize files and noncanonical JSON. Windows DACL protection is the
reviewed provisioning writer's responsibility; Node metadata does not attest a
Windows ACL. The loader never injects the enable flag.

No key is generated by these modules. Provisioning, hosted immutable Storage
acceptance and deliberate feature activation are separate release operations.
The development launcher continues with new document uploads unavailable after
a known private-configuration failure; unexpected core failures remain fatal.
