The prior documentation pass ran only CLI65.8.0 `project pause --help` to verify this syntax; this update ran no CLI/provider command. [Official project documentation](https://vercel.com/docs/cli/project#pause)
defines production-traffic pause. [Official Daemon management](https://vercel.com/docs/daemons/managing-daemons#stopping-a-daemon)
states that project pause stops that project's daemon instances; resuming the
project starts them again. It also supports a zero-instance override in **every**
active region, which persists across redeployments. Pausing the web alone does
not stop the separate worker project.

Before stopping a live worker, stop admitting new work and reconcile any in-flight
lease and owned Sandbox cleanup; preserve unknown outcomes rather than replaying
jobs. After the two pause requests, independently verify paused project state,
the stable web origin's `503 DEPLOYMENT_PAUSED`, zero worker instances and exact
owned Sandbox/session/snapshot absence. A pause reply alone is not cleanup proof.
Check the actual web deployment target and direct preview URLs separately:
production pause does not establish that every preview URL is inaccessible.
Capture only closed status/identity metadata, never raw logs, tokens or config.
Do not delete either project, its VCR images, central records or historical
receipts as a substitute for stopping the pilot. No stop or provider operation
was executed while writing this guide.
