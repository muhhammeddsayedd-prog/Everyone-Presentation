# Owned trace-table native ACL proof

Source preparation only. The entry is initially disabled; no prepare, claim,
SQL, provider or original-database write has been performed by its authors.
This purpose can prove one table's native privilege semantics. It cannot pass
recovery36, admit a profile exception or prove media/Storage/Auth restoration.

The actual failed5d run captured thirteen catalogue differences and completed
all cleanup/preservation checks. Its one new pair is exactly
`tables|eps.job_stage_attempts|acl`: source `{postgres=arwdDxtm/postgres}`, restored
NULL. Observation pins the actual receipt, seven-file archive and public pair.
All129 actual source bytes remain exact. The other twelve differences retain
their historical exact profile planners; this proof does not newly admit them.

The compiler imports the sealed metadata36 compiler, substitutes only the new
inert runtime factory, disabled gate, purpose/receipt scope and source closure.
Its fresh UUID inherits exact owned database name/OID/marker admission, same
functional34–36 DDL, synthetic fixture, checksum-bound dump, original29 full
catalogue/data/Auth/Storage/global-role checks, three-role cleanup and shared
lock release. Old084/c0/5d identities/claims are never replayed. The six new files
plus three public references are separately sealed at prepare/execute.

The wrapper delegates every other profile invocation unchanged. Only the owned
restore database at `populated36-metadata-dump-restore`, with the identified
NULL/explicit pair and captured thirteen-difference count, enters the probe.
Target table/column/constraint/index/policy/trigger/function/schema metadata must
match the source except for that exact ACL. Before the existing profile helper
would run, a unique in-memory sentinel ends this native-only slice. Neither a
message-matching catch nor a fabricated successful restore is used.

Within the owned restore transaction, snapshot the exact NULL ACL; establish a
savepoint; `GRANT ALL PRIVILEGES ON TABLE eps.job_stage_attempts TO postgres`;
require the exact observed owner-only ACL; snapshot; rollback the savepoint and
require the raw NULL snapshot again. No system-catalogue UPDATE or role adoption
occurs. Compare expanded ACL grantor/grantee/options in both EXCEPT directions;
all eight PG17 table privileges and all fourteen columns' four privileges for
every real role plus PUBLIC, each with and without grant option; schema USAGE
and CREATE; owner, RLS/FORCE, column grants, policies, constraints/FKs, triggers,
role identities/attributes and memberships. Require complete closed matrices,
zero symmetric differences, equal metadata outside the ACL and exact rollback.
The full portable catalogue must also equal its pre-probe state after rollback.

Full native rows are private exclusive artifacts. Public output contains counts,
hashes and closed pass flags only. Native proof must return normally, include
actual source seals and pass inherited full cleanup before root may separately
author/review any exact one-table restore adapter. A failed or ambiguous run
retains its immutable claim; no automatic retry, old-controller replay, broad
NULL-ACL exception, trace disable or cloud change is supplied.

PostgreSQL17 documents that [NULL ACLs use the hard-wired object defaults](https://www.postgresql.org/docs/17/catalog-pg-default-acl.html),
not current `pg_default_acl` entries. Its [privilege inquiry functions](https://www.postgresql.org/docs/17/functions-info.html#FUNCTIONS-INFO-ACCESS-TABLE)
support PUBLIC, the eight table/four column privileges and `WITH GRANT OPTION`.
Those documents motivate the experiment; they do not replace its native proof.
