# Bounded real English-normalization component check

These reviewed helpers separate source discovery from one paid request. Neither
is a browser, acting-user API, database-write or complete processing acceptance
test. The existing source preparation binds the permitted IMG_2850 video hash.
The unrelated retained transcription probe is deliberately not reused.

`lookup.py` pins the read-only SQL, exact linked canonical project and current
video/preparation SHA. It claims once, dispatches a unique checked SQL snapshot,
captures bounded CLI output in RAM, requires exactly one canonical source and
scan-job join, then saves original text/bindings only under ignored `.local/`.
No raw CLI response, stderr or private transcript enters a public receipt.

`normalize-once.mts` requires that private binding and a private
`.local/m03-english-component/owner-confirmed.json` object with the existing
owner-confirmed `name` and `age`. Ground truth must come from the owner's stated
facts, never another model result. It checks exact original SHA, one bounded
chunk, existing private worker model/key, then claims permanently before its
single Responses request. A failure remains a failure; there is no automatic
replay or claim deletion.

The public receipt has only case alias, fixed checks and actual provider metadata.
It tests faithful English availability and the already confirmed name/age only.
It makes no broader semantic-accuracy, database-persistence, app, guest, n8n or
immutable-version acceptance claim. No new transcription is started.

Offline parser tests:

```powershell
python -X utf8 -B -m unittest discover -s development/m03/english-component -p test_lookup.py
```

The coordinating root reviews helper/query bytes before dispatching the lookup
or normalization. Readiness/source failures do not authorize choosing another
person or source.
